# 安装与配置

插件面向 Windows 与 macOS 桌面，最低 Obsidian 版本为 1.6.0，要求 Git 2.40+。执行 `npm ci`、`npm run package` 后，将 `dist/cloudnote/` 中的三个文件复制到测试知识库的 `.obsidian/plugins/cloudnote/`，在 Obsidian 第三方插件设置中启用。当前是待验收构建，尚未发布到社区目录；服务端准备见 [部署说明](server.md)。

## 首次连接

填写 Git 可执行文件、SSH 远端地址及设备名称，先测试连接，再预览初始化范围并确认。Git 可以填写 `git` 或绝对路径；图形应用未继承终端 PATH 时应使用真实可执行文件路径，并确认 Git 调用的 SSH 能访问 Agent。插件只管理自己创建的仓库，遇到现有非云笺仓库或位于其他 Git 仓库内部的知识库，会要求使用独立目录。

空远端会收到首次提交，已有远端会先获取并比较文件。首次连接时，一方单独存在的路径均保留，不把首次缺失视为删除，同名内容不同则进入冲突处理。同步范围包含 Markdown、图片、PDF 和 Canvas 等普通文件，排除 `.obsidian`、`.trash`、`.git` 与云笺临时数据，超过 100 MiB 或符号链接等项目显示跳过原因。

## 同步与冲突

立即同步按保存本地提交、获取远端、比较整合、推送的顺序执行。自动同步默认关闭，连接测试成功后可以开启，编辑停止 3 秒触发，每 30 秒检查远端，未完成预览或冲突时暂停继续。概览区分待提交文件、待推送提交、待拉取提交与冲突，只有云端流程成功才更新最近成功时间。

单独拉取会预览新增、覆盖和删除，取消不应用文件变化。本地有未提交修改时先使用仅保存本地提交，已有未推送提交则可确认整合，但保持待推送状态。确认时重新检查远端和受影响文件；涉及写入范围的新编辑会阻止覆盖，与写入无关的编辑保留到下一批。

冲突弹窗展示双方设备、路径和内容，附件可分别另存查看。选择使用本地、使用云端或保留双方，所有冲突选择完成后才可确认应用；保留双方会将云端内容放在原路径，本地内容另存为带设备名称和时间的副本。整合提交保留双方父提交，因此未选择的内容仍可从历史找回，原笔记不写入冲突标记。

## 历史、快照与新设备

版本历史可以输入精确相对路径查询已删除文件，以每页 100 条记录翻页访问完整历史，并在当前页搜索说明、哈希或设备。文件历史支持内容和文本差异查看、历史附件另存，以及恢复预览；整库快照用带注释 Git 标签保存，并在同步时上传。恢复先保存当前修改，再预览新增、覆盖和删除，确认后创建新提交；要撤回恢复，选择恢复前提交再次恢复即可。

新设备下载需要输入已存在的空目录绝对路径。插件会创建受管仓库并获取、校验和应用云端内容，下载后将该目录作为知识库打开；因为 `.obsidian` 不参与同步，仍需安装插件并填写同一远端。设备标识会独立生成，设备视图仅展示最近提交时间，不表示实时在线状态。

## DeepSeek

AI 默认关闭，开启后发送固定待提交对象的文件名与文本差异，也可选择只发送文件名与变更类型。附件不发送二进制内容，输入按路径排序，最多 24 KiB 并标注截断，10 秒超时、缺少 Key、限流或响应无效时回退默认说明。无变更、单独拉取、推送已有提交和同步重试不会重复调用 AI，说明最多 120 个 Unicode 字符。

默认模型为计划指定的 `deepseek-flash`，可按账号实际可用模型修改。Key 输入后点击保存，使用 Obsidian SecretStorage（1.11.4 起提供），旧应用版本仅保存在当前插件会话内存，重启后需重新输入。空输入框点击保存可以清除 Key，普通插件设置只保存秘密名称，不保存明文 Key。
