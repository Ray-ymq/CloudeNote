## 实现结果

插件通过参数数组调用本机 Git，使用非交互 SSH Agent 认证，先保存本地提交，再获取、比较和整合远端，最后推送。同步范围覆盖普通笔记和附件，排除配置、垃圾箱与临时数据，跳过超限文件及符号链接，并在写入前检查路径、大小写和 Unicode 碰撞。首次连接采用并集保护，单独拉取支持预览与取消，已有本地提交保持待推送状态，自动同步与 AI 初始关闭。

冲突使用逐文件三方比较，同一文件不调用自动文本合并，提供使用本地、使用云端和保留双方选择。整合提交保留双方父提交，历史可按提交与路径查询，支持文本差异、附件另存、已删除文件恢复与创建新提交撤回恢复。快照采用 `cloudnote/snapshot/` 前缀的带注释标签，随同步上传，并可在新设备查询及恢复。

文件写入采用固定 Git 对象、临时索引、操作副本与日志保护，正式替换时保留实际原文件，再通过不覆盖现有文件的原子硬链接发布新内容。进程中断后按日志恢复，检测到后续编辑时保留当前内容及保护副本，同一知识库的修改任务使用队列和进程锁。该机制要求知识库所在文件系统支持同卷硬链接，NTFS 和 APFS 为适用目标，其他文件系统需要在验收时确认。

Obsidian 中提供同步概览、版本历史、整库快照、冲突处理、连接设备和插件设置六个原生视图，状态栏区分待提交、待推送和失败状态。DeepSeek 使用固定待提交对象生成中文说明，文本输入最多 24 KiB，附件仅发送名称，10 秒超时或接口失败回退默认说明，重试与无变化不重复调用。API Key 使用 SecretStorage，旧版应用仅在会话内存中保存，普通设置只保存秘密名称。

## 待项目验收

需要在 Windows 和 macOS 的真实 Obsidian 中验证安装、六个原生视图、自动同步时机、SecretStorage 与旧版会话回退。需要使用两台桌面设备及私人 Linux SSH 裸仓库验证新增、修改、删除、重命名、首次连接、冲突传播、快照下载及历史恢复。真实断网、SSH Agent 失败、磁盘空间不足和应用进程中断也应实机检查，真实 DeepSeek 冒烟测试仅在提供测试 Key 后进行。

本地测试不能证明 macOS、Obsidian 编辑器文件监听或真实 SSH 环境已经通过验收，因此当前版本保持待验收状态。验收通过后再发布 `0.1.0`，本次没有发布插件、创建发布标签或部署私人服务器。服务器独立备份仍是必要运维工作，Git 历史不能替代磁盘损坏后的备份恢复。
